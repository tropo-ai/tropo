# full-release-validation

<!-- nav-block:start -->
**📍 Vault Path:** [tropo-subsystems](aae9a37b.md) → [Tropo Playbooks](76bab75f.md) → **full-release-validation — release-pipeline step**
<!-- nav-block:end -->

The full paranoid validator, over the final assembled release state, bound to one
`package_sha256`.

This is the release-side home of the full pass. Dev runs get incremental, registered
validation; the exhaustive sweep belongs where a release is being decided (Mike's
two-pipeline ruling, and brief 5d192c3c's split of gate from firehose).

The [activation-bound release-validation gate](../tools/tropo-release-validation-gate.py)
reruns the full validator in release mode and compares it with this same release
activation's Assemble baseline. Aggregate summary prose is not an identity: the gate
compares per-section FAIL/ERROR line counts, reported section tallies, and exact
ANSI-stripped specific findings. It preserves UIDs and paths, accepts removals, and refuses
new or increased debt. Validator execution outside the documented 0/1 result contract is
an operational failure, not a comparison pass.
