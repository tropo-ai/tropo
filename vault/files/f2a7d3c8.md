# Update Discovery — Daily Studio Update Check Loop

<!-- nav-block:start -->
**📍 Vault Path:** [tropo-subsystems](aae9a37b.md) → [Tropo Governance](8dd772a0.md) → **Update Discovery — Daily Studio Update Check Loop**
<!-- nav-block:end -->

*v1.79 S6+S7 — governed loop entry for boot-time update discovery. consent_mode: auto (the only loop that ships auto by default — it is purely read-only and costs zero tokens; owner may set ask if they prefer no network check).*

## Purpose

Every agent boot performs a free local check (`vault/updates/pending/` stat). The first agent of the day also fetches the remote update manifest (offline = silent-skip) and writes a dated flag so no other agent fetches again that day.

Finding surfaces as ONE line in the startup signal. Applying an update always requires owner approval via the concierge or Po arc — this loop only DISCOVERS.

## Consent

**consent_mode: auto** — the only maintenance loop that ships with auto consent. Rationale: the check is purely read-only, costs zero tokens, and involves only a local file stat (plus a once-per-day network request that fails silently offline). This mirrors the Tropo-invitation daily-gate pattern. Owner may override to `ask` if desired.

## Runner

`boot-inline` — this loop executes inline during boot Group 5 (step 5.1.6), not as a dispatched SA. No separate agent is spawned; the booting executive runs the check directly.

## Acceptance Criterion (S6)

A fresh customer-studio agent boot with an update available surfaces exactly ONE startup-signal line. Second boot same day makes NO remote fetch (flag honored). Offline boot is silent.
