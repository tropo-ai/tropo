# validate-release-plan-fan-in

<!-- nav-block:start -->
**📍 Vault Path:** [tropo-subsystems](aae9a37b.md) → [Tropo Playbooks](76bab75f.md) → **validate-release-plan-fan-in — release-pipeline step**
<!-- nav-block:end -->

Every dev-spec named by the locked release-plan is `done`, with accepted evidence, and
unreserved by another live release.

Each row binds dev-spec UID and SHA, dev activation and run, the tested final commit,
the completion receipt hash and the acceptance-evidence hash (§4). A row that cannot
produce all of those is not a shortcut to fix — it is a dev-spec that has not finished.

The [activation-bound release-validation gate](../tools/tropo-release-validation-gate.py)
runs that existing AC5 verifier first. Only after AC5 passes does it run the full validator
in release mode and write one immutable baseline into the correlated release run folder.
Validator exit 1 is evidence of the Studio's known debt, not an operational failure; exit
outside 0/1 or a missing terminal summary refuses capture.
