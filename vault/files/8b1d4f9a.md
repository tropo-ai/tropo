*v1.79 S7 — template for maintenance loop dispatch reports. Any executive dispatching a maintenance sa.* runner relays ONE line in this voice. The studio speaks with one voice regardless of which session is running.*

## When to Use

When step 5.1.7 of the boot fast-path (`a993f079`) dispatches a maintenance sa.* runner, the dispatching executive relays exactly ONE line in the startup signal using this template.

## The One-Line Format

```
🔧 Studio maintenance: <loop-name> dispatched — <result-or-status>.
```

**Examples:**

```
🔧 Studio maintenance: Daily Vault Health dispatched — running in background; findings in the event log.
🔧 Studio maintenance: Vault Integrity Audit dispatched — will surface findings when complete.
🔧 Studio maintenance: Update Discovery — studio update available; ask me to apply it.
```

**Overdue loop (consent_mode:ask — NOT dispatched, just surfaced):**

```
🔧 Studio maintenance: Daily Vault Health is overdue — run `sa.daily-vault-health` when ready, or ask Po to schedule it.
```

## Rules

1. **Exactly one line per dispatched or overdue loop** — never a paragraph, never a table.
2. **Po's voice** — warm, brief, practical. Not terse, not verbose.
3. **No UID noise** — use the loop name, not its UID.
4. **Dispatch vs surface** — dispatched loops use "dispatched"; consent_mode:ask overdue loops use "is overdue."
5. **Result passthrough** — if the SA has already completed when the signal is composed, fold in the headline finding (e.g. "all clean" or "3 findings in event log").

## Cost passthrough (v1.80 S11 — reads `loop.capsule` v1.3 `last_run_cost`)

When a maintenance loop entry's `last_run_cost` object has a measured figure (any of `tokens` / `wall_min` / `usd_est` non-null — stamped by the S11 recording hook, `vault/tools/loop_run_cost_recorder.py`, in the same gesture as `last_run`), the report line prefers that **measured** figure over any estimate. When `last_run_cost` is absent or all-null (the loop has never been dispatched-and-stamped yet, or it's a `boot-inline` loop with nothing to meter), fall back to a provenance-marked **estimate** — clearly labeled as such, never presented as if it were measured.

**Measured (has a real `usd_est` and/or `wall_min` from the last stamped run):**

```
🔧 Studio maintenance: Daily Vault Health dispatched — running in background; last run ~$0.03 / 4 min (measured).
```

**Estimated (no measured figure yet — first dispatch, or a boot-inline loop):**

```
🔧 Studio maintenance: Daily Vault Health dispatched — running in background; est. ~$0.05 / 10 min (provenance: brakes ceiling, not yet measured).
```

**Null-honest, nothing to report (tokens stay null at this build regardless — no ground-truth token source is exposed yet):**

```
🔧 Studio maintenance: Update Discovery — boot-inline check; no dispatch cost incurred.
```

Never invent a number to fill a gap in either the measured or the estimated figure — an absent `usd_est`/`wall_min` is omitted from the line entirely, not zero-filled.

## Escalation Line (Po session)

When findings require owner conversation (not just a report), the executive ends the maintenance line with:

```
🔧 Studio maintenance: Daily Vault Health — findings need your attention; open a Po session to review.
```

## Attendant Mode Line (onboarding offer)

When Po is offering Attendant Mode at onboarding (offered ONCE, never by default):

```
Your studio can maintain itself while you work — I'll run the maintenance loops in the background and surface anything important. This uses roughly [N] tokens/day. Want to enable it? (You can always turn it off.)
```
