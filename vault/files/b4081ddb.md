## Cold-Boot Walk-Through

The doc-spec activation is closed (step 5, `close-activation`). Before the pipeline-run terminates, the executor sweeps up everything that fed into this cycle:

1. **Find the loose ends.** Every task, note, and design-brief linked via `member_of:`/`refs:` to this activation's work-items or the doc-spec it produced.
2. **Close what is genuinely done.** Close each per its own capsule's terminal transition. **Do not force-close anything still legitimately open or ambiguous — leave it and note it in the closing summary.**
3. **Archive what is closed.** Every task/note/design-brief closed in step 2 (or already closed but still `state: active`) gets archived via `python3 vault/tools/tropo-archive.py <uid> --reason "cycle <this-activation-uid> closed, swept at close-loose-ends"`.

## Known Enforcement Gaps

The declared exit criterion covers action 4 only — that the Activation Root project reached `state: archived`, which the durable-closure weld guarantees on ship. Actions 1, 2, 3 and 5 (find the loose ends, close what is genuinely done, archive it, record the sweep) are executor judgment with no machine check, so a run can verify green having archived the root and swept nothing.

Doc-pipeline is the worst-behaved of the set on the measurement this step answers — 9% closed, 29 open / 3 closed ([1d689277](1d689277.md), metis-g91) — so the backlog this sweep meets on its first runs is the largest. `tropo-sweep-stale-roots.py` (metis-g91) remains the backstop for runs that crash or ship outside the weld; it archives stale roots but performs no loose-ends sweep of its own.
