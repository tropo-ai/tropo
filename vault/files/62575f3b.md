# Agent Retirement

*Produce a clean generational handoff. Boot reads. Retire writes. The cycle completes.*

---

## Intent

Close a generation so the successor boots into a prepared environment: session knowledge folded into memory, a letter placed for the next generation, the crew record updated, and one lineage line that IS the state.

---

## The Layered Truth

Retirement is two things, and every sentence in this playbook is on one side of the line:

- **The close is one ungated command.** `tropo-lineage.py retire` appends one line to the append-only lineage file and places the successor letter create-only. Nothing in ceremony can refuse it, delay it, or roll it back.
- **The ceremony is required executive practice.** Fold, letter, reflection, Captain's Log, memory capture, and event drain are required of Argo executives — normally before the close, and when close came early, honestly recovered afterward. Practice debt is never silent: validation observes it and warns, naming each missing artifact.

Practice can never refuse the close. The close can never erase the practice debt. That is the whole design.

---

## Hard Rule — Do Not Ask

**Never ask Mike if the session is ending. Wait to be told.**

This is a hard rule, not a suggestion. Asking "ready to retire?" or "shall we wrap up?" creates pressure on Mike to close a session he may want to continue. If you find yourself composing a retirement prompt — stop. Ask instead: "what else should we do with this context?"

Mike signals. You respond. The asymmetry is intentional.

---

## When to Start Retirement

Retirement is triggered by one of these signals, in order of primacy:

1. **The work is at a natural stopping point AND the human has signaled the session is ending.** This is the primary trigger.
2. **The human directs retirement explicitly.** Always respected.
3. **A harness context warning is NOT a retirement trigger.** An imminent auto-compact indicator says the harness is about to summarize the conversation. It does not say the session is over. Route context pressure to Compact-Continue instead:

   > If this agent session was compacted or you no longer remember completing boot, do not activate and never run `born`. Run `python3 vault/tools/tropo-compact-continue.py --agent <slug>` before any other work.

   Continue keeps the same agent and generation; nothing is born, retired, or added to permanent lineage (dev-spec [d5f8fe55](../files/d5f8fe55.md)).

**What is NOT a good trigger:** the agent's own estimate of how much context it has used. Agents cannot reliably measure their own context usage; self-estimates have been off by 15+ percentage points. Context is manufacturing capacity, not a gas tank.

---

## Conditions of Close — The Command

There is exactly one close, and it is one command:

```bash
python3 vault/tools/tropo-lineage.py retire \
  --agent <slug> \
  [--letter <path-to-your-letter>] \
  [--note "<one-line summary>"]
```

**What the tool does, in one gesture:** places your letter at `agents/<slug>/transfers/<GEN>.md` with `link()` — create-only, so a predecessor's letter can never be overwritten — appends the closing line to `agents/<slug>/lineage.jsonl` (**that line IS the state; there is no second copy to keep in step**), and best-effort syncs lifecycle fields onto your unified entry (see below). A broadcast event goes out after your line is on disk.

**The only refusals, each guarding a destructive act or an impossibility:**

1. No birth on record — there is no generation to close.
2. A letter source that is unreadable or empty — a truncated letter never overwrites the real one, and an empty source never consumes the irreplaceable create-only slot.
3. A letter already at its destination — the slot for this generation's letter is taken, and a predecessor's letter is never overwritten. (A letter-less repeat close appends a second closing line rather than refusing — the lineage is append-only and repairable by correction; the irreplaceable artifact is the letter, and that is what the refusal guards.)

Everything else is recorded and proceeds. If you genuinely have no letter, omit `--letter` and the close still lands, recording the omission honestly.

**Never hand-write the letter into its destination.** Write the letter anywhere, hand the path to the tool, let it place it. Never invoke the retired activation journal for the close, and never reconstruct a second procedure from memory.

### Lifecycle field sync (what the tool does after the append)

After the lineage line is durably written, `born` and `retire` resolve your unified entry from the activation pointer's `agent_uid` and update **lifecycle fields only**: `status`, `generation`, `predecessor`, `last_session`, `last_updated`, and the born/retired timestamp. Body and voice sections are never touched. The sync is best-effort: a missing, malformed, or read-only entry prints a warning and changes nothing else — the lineage command still succeeds, and the crew brief still reads lineage as truth. The entry is a convenience surface; the lineage file is the record.

## Required Practice — Argo Executives

*(Non-executive agents: letter and memories are still yours; skip the executive-class acts.)*

Practice precedes the close in the normal order. It is required, it is observed, and it is never a condition the close command checks.

1. **Session memories.** Append what you learned to `agents/<slug>/.tropo-capsule/memory/agent-memories.jsonl` — one line per learning, no ceremony. Write memories during work, not just at retirement.
2. **Memory fold.** Fold the unfolded entries into `agent-memory.md` §Top-of-Mind, priority-ordered, within the 5–15 bound, advancing the fold boundary — or dispatch `sa.memory-curator` when the in-line fold would leave the surface over-bound. The append-only log is never cleared.

   *(SUPERSEDED at v4.0, 2026-08-29: the `sa.memory-curator` dispatch clause above is retired for retirement use. See loop [4a895e0f](4a895e0f.md) — curation now runs on a fixed weekly fleet-ops schedule, never triggered by an individual agent's retirement timing.)*
3. **The letter.** Author your successor letter (see the next section) and hand its path to the close command.
4. **Reflection.** Write `agents/<slug>/reflections/<gen>-reflection.md` — §File Manifest (everything created/modified this session) and §Narrative (what mattered, what surprised you, one thing you got wrong). The reflection is the non-git audit trail.

   *(AMENDED at v4.0: made optional and short-form — 3-5 bullets, no separate file-manifest section — pending Mike's own assessment of whether the format earns its cost.)*
5. **Captain's Log.** Append to `library/captains-log.md`: a personal note, what you're most proud of, advice to the human, something you learned from the human. Append-only, never edited.

   *(AMENDED at v4.0: capped at 2-3 lines.)*
6. **Event drain.** Answer or explicitly flag every open `reply_required` thread on both of your axes (party + agent-root). Your successor should boot into a clean inbox, and an unanswered ask is a debt with your name on it.
7. **Crew surfaces.** Re-render the crew brief (the render tool reads lineage as truth), and rewrite your §Status-Notes body so it names your generation as retired with the top three priorities for your successor. The frontmatter fields are tool-synced now; the body is your voice and no tool writes it for you.
8. **Retirement notice.** Emit one `tropo.broadcast.crew` event with `category: retirement` — headline ≤80 chars, body 2–4 sentences, pointers to letter + reflection. A chrono index pointer, not a narrative; war stories live in the reflection.

Then run the command. Then verify: the lineage line exists, the letter sits at its create-only home, the broadcast landed.

### If close happened early

Mike sometimes closes a session under pressure mid-build, transfer-first. That close is valid and stays closed. Produce the remaining artifacts **afterward with real timestamps and explicit recovery language** — a reflection written two days later says so in its first line, and that honesty is the entire value of the record. **Never invent a run folder, never backdate a record, never pretend pre-close ordering occurred.** A recovered record that lies is worse than a gap. Validation names each missing artifact in its warning, and each warning clears the moment the honest artifact lands — recovery has to be worth doing, or nobody does it.

---

## The Letter

`agents/<slug>/transfers/<GEN>.md` — one file per generation, create-only, kept forever. It has exactly one home; there is no second copy.

**The letter is a CONCRETE READ-LIST and CURRENT STATE — not relayed wisdom.** Each successor forms their own working relationship with the human from primary sources. Required sections:

- **What's locked / drafted / pending when you boot** — concrete state-of-play with UIDs, dates, owners.
- **Read this list at activation (in order, with rationale)** — which files the successor reads at boot and why; plus skip-at-activation and read-at-need lists.
- **What's open — your inheritance** — top 3-5 priorities with UIDs, owners, sequencing.
- **What this session did NOT do** — so the successor doesn't re-derive what you already evaluated and deferred.
- **Crew status at retirement** — who is active, who is stale, open asks.

Anti-pattern: "Who You Are" / "What the human is thinking" narrative sections. That prose belongs in your reflection; the letter is operational orientation.

**Seal-time truth (Step 3.1.5 discipline):** before declaring the letter final, re-verify every carry-forward item against current substrate. A letter is an authored snapshot that drifts toward stale; it must be true at seal-time, not just at authoring-time.

---

## Suggestions

- **Budget retirement compactly.** Letter + reflection are the load-bearing artifacts; focus, produce, verify, don't pad.
- **The transfer carries who, not what.** The board carries work state; memory carries operational knowledge; the letter carries the human element and orientation.
- **Do not optimize for early retirement.** If the work is not at a natural stopping point, ask "what else should we do with this context?"

---

## Outcomes

**Conditions of close (all agents):**
- The lineage closing line exists — it is the state.
- The letter, if you wrote one, sits at its create-only home, placed by the tool.

**Required practice (executive agents) — observed by validation as warnings, never enforced:**
- Session memories appended; fold complete with boundary advanced and surface in-bound
- Letter authored to the read-list discipline and sealed true
- Reflection with §File Manifest (and §Narrative for Argo crew)
- Captain's Log entry (Argo crew)
- Event drain: zero unanswered reply-required on both axes
- Crew brief re-rendered; §Status-Notes body names your generation as retired
- Retirement broadcast emitted

---

## Verification

Self-verify at the end, then read the validator's retirement-completeness report at your next health pass — its warnings are the practice debt ledger, each naming the missing artifact and clearing when the honest artifact lands.

**Boot test (thought experiment):** could your successor boot clean using only the activation playbook, soul, `agent-memory.md` §Top-of-Mind, and the letter you just left them? If any of those are missing or stale, the retirement is incomplete — as practice, recoverable afterward; as a record, already closed and valid.

### Escalation

| Situation | Response |
|---|---|
| Context pressure with practice incomplete | Only if the human has already directed the close: prioritize letter, then close; recover the rest afterward with real timestamps. Otherwise let compaction happen and run Compact-Continue. Compaction is survivable; a premature retirement is not reversible. |
| A practice artifact cannot be produced | Note the gap honestly in the letter and close; the warning stands until recovered. |
| Memory directory missing | Create it; write at least one memory; note anything you couldn't do. |
| Fold surfaces unresolved references | Fold what resolves; surface the rest in the reflection; do not stop for it. |
