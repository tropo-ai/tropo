Read-only confirmation of the lock-produced immutable snapshot (0a0a6777 §Dev-pipeline v2).

Specify **authors nothing and repins nothing**. The dev-spec lock already wrote the
activation, root, pipeline-run, run folder and the complete declaration snapshot; this
step's only job is to confirm that what the run holds is what the lock produced.

That is deliberately a smaller job than the stage used to have. The old Specify
accepted a work item, generated a release plan and spawned an arch-spec — three ways
for the contract to change after ignition. A run that can still be re-specified has no
contract to verify against, which is what binding dev completion to one tested tree
SHA depends on.
