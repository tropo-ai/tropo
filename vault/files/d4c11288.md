# RELEASING — the coupled release flow

<!-- nav-block:start -->
**📍 Vault Path:** [681516fe](681516fe.md) → **RELEASING — the coupled release SOP (build → stage → sign...**
<!-- nav-block:end -->

*One flow, two human gestures. Nothing goes public until a human fires it; nothing claims LIVE until the remote confirms it; nothing stays silently unpublished — every release ends `live` or `deferred-by-mike`.*

## Ship contract

This entry governs the release semantics. The stranger-facing file is authored at `vault/templates/root-docs/RELEASING.md`; ship-artifact `1a7b53c5` copies it to recipient-root `RELEASING.md`. The explicit manifest edge is load-bearing: `box_path` names the destination but does not itself make a file ship.

**Which publisher is this?** This SOP covers `tropo-publish-release.py` — the **OS release** publisher (GitHub + distribution channels). It is NOT `tropo-publish.py`, which is the *federation team-vault* publisher and never touches release channels. If you are shipping a Tropo-OS version, you are on this page.

## The flow at a glance

```
1. BUILD    python3 vault/tools/tropo-build-release.py --bump <patch|feature|release>
            → fully PRIVATE: zip built, nothing uploaded anywhere.
            Step 0.5 pre-flights publish-state (drift INFO, anomaly refuses, --offline records itself).

2. SIGN     Mike's human signoff via the pipeline ceremony (action_human_signoff) — gesture 1.

3. STAGE    python3 vault/tools/tropo-publish-release.py --version X.Y.Z
            → syncs the extract into the publish clone (surgical: preserve-list honored,
              would-delete list printed, refuses on a non-allowlisted deletion),
              asserts CHANGELOG equality, commits + tags LOCALLY,
              DISABLES the clone's push URL (physical guard),
              records {staged_sha, tag, version}, prints the EDGE SUMMARY. State: STAGED.
            Still private on every channel.

4a. FIRE    python3 vault/tools/tropo-publish-release.py --version X.Y.Z --fire     — gesture 2
            → TTY-interactive confirm (default NO; piped input refuses),
              re-runs the outward gate, refuses if the clone moved (STALE-STAGE),
              pushes main + tags, creates the GitHub Release with the zip asset,
              uploads the Supabase zip + update manifest,
              then VERIFIES LIVE: tag on remote + main == staged sha + release object exists.
              Full green → publish_state: live, event emitted, entry stamped. Anything less
              screams with a named state (below) and a cure.

4b. DEFER   python3 vault/tools/tropo-publish-release.py --version X.Y.Z --defer    — Mike's gesture
            → same TTY discipline as fire. Records {deferred_by, deferred_at, reason} on the
              release entry. The builder REQUESTS the skip; Mike's hand AUTHORIZES it.
              A deferred release is boot-line-silent and stays fireable later.
```

## Verifying a release before signoff (the external-test gate)

*Folded by Vela V68 2026-07-19 from the v1.85.0 external-test finding (dev-pipeline run `0450cae2`, step `bc6b17ec`; evidence at `vault/pipeline-runs/dev-pipeline-0450cae2-2026-07-15/external-test-result.md`). Argus A130 drafted the flow; this section is the verification discipline the flow was missing, discovered when the v1.85 external-test could not be executed as literally worded.*

**The build is non-deterministic by construction.** `tropo-build-release.py` embeds wall-clock `datetime.now()` in four shipped locations — `MANIFEST.md` (`Generated: YYYY-MM-DD HH:MM`), `version.md` released-date, the `built_at` provenance stamp, and the vendor-refs manifest — and packages the zip via `shutil.make_archive`, which bakes filesystem **mtimes** into the archive. Two builds of byte-identical source therefore produce **different** zip and manifest `sha256` values. The manifest digest would only reproduce if rebuilt in the same UTC **minute**; the zip digest depends on per-file mtimes that differ on every checkout.

**Consequence for the recorded digests.** A release's recorded `zip_sha256` / `manifest_sha256` are **fixity** digests of the one canonical artifact **on the host that built it**. They verify that exact file where it was built. They are **not** an independently-reproducible acceptance gate — "rebuild elsewhere and match the digest" cannot pass by construction, and a mismatch there is a **false FAIL**, not a real defect.

**The correct cross-machine verification model** — what the external-test step should assert when verifying a build produced on another machine or federated clone (the real crew topology):

1. **Content-equivalence.** Rebuild from the release's recorded source commit in an isolated worktree; confirm the substrate is green — `tropo-validate.py` reports **0 failed** and `tropo-rebuild-vault.py` exits **0**. This proves the shipped content is sound, independent of packaging timestamps. (Note: a fresh worktree has no index — `vault/00-index.jsonl` is gitignored — so the *first* rebuild writes it and the dirty-state guard returns non-zero; this is a fresh-checkout artifact, not a defect. Re-run once; a current index exits 0.)
2. **Fail-closed evidence (L2.3).** Confirm the release machinery **refuses** on a red validator, a missing pipeline-activation key, or a stale/uncurrent substrate — and that the refusal is **not bypassable** (`TROPO_SKIP_ENFORCEMENT_GATE=1` does not override the substrate-currency guard; `build-release` standalone refuses with "No key, no build"). Observing a guard fire is positive evidence the gate works.
3. **Fixity — build-host only.** Verify a recorded `sha256` against the canonical artifact on the machine that produced it. That is the only place the digit-for-digit match is meaningful.

**Forward fix (recommended increment; tooling lane = Argus/Talos, SOP lane = Vela).** Give `tropo-build-release.py` a **deterministic mode**: honor `SOURCE_DATE_EPOCH`, normalize archive mtimes (or write the zip via `zipfile` with a pinned `date_time`), and pin/remove the four `datetime.now()` stamps. Once that lands, digest reproduction becomes a coherent cross-machine gate and the external-test step can be re-specified to require it. Until then, external-test acceptance is **content-equivalence + fail-closed + build-host fixity**, never independent digest reproduction. This is the structural reason the v1.85 external-test assignment survived three Vela generations (V66→V67→V68): as literally worded ("reproduce the recorded digest"), it is not executable in an independent clone.

## The states you can land in (all named, all with cures)

| State | Meaning | Cure |
|---|---|---|
| `STAGED` | Committed + tagged locally, push URL disabled, nothing public | Fire or defer. Re-running stage is idempotent (clean tree + matching tag → exit 0, no new commit) |
| `STALE-STAGE` | The clone moved after staging (HEAD ≠ staged sha) | Re-stage; fire refuses until the stage is fresh |
| `PUSHED-NO-RELEASE` | Push landed, GitHub Release creation failed | Re-fire — idempotency keys on the release object and completes it |
| `POSTED-UNVERIFIED` | Fired, but verify-live could not confirm (network) | Re-fire (verify-only path); never treated as live |
| `live` | Remote confirmed: tag + main sha + release object | Done. `published_at/tag/fired_by` stamped |
| `deferred-by-mike` | Mike authorized skipping this version | None needed. Fireable later; boot line stays silent |

**Drift** = a built version that is neither `live` nor `deferred-by-mike`. It nags: one boot health line for every agent, and the next build's pre-flight flags it. Silence is not a legal state.

## The preserve-list (stage's surgical sync)

The extract does not contain repo-community files; stage must never delete them from the publish clone: `.git/`, `.github/` (issue + PR templates, workflows if any), and any file enumerated in the preserve-list block of `tropo-publish-release.py` itself (the tool's list is canonical; this SOP names the *rule*). Stage prints every would-delete path and **refuses** on anything outside the allowlist — if that fires, the fix is extending the extract or the preserve-list deliberately, never forcing.

## Changelog discipline (unchanged, now checked twice)

Entries are written under `## [Unreleased]` in `argo-os/CHANGELOG.md` *as changes are made*; promotion to `## [X.Y.Z] — date` (+ link refs) happens **before build**, and the outward gate's changelog check rides both stage and fire. Stage additionally asserts the extract's CHANGELOG equals argo-os's — divergence fails loudly and the cure is rebuild, never hand-sync.

## Attested-class releases (no pipeline run)

A release closed by attested-manual ceremony has no run folder, so stage/fire **refuse it — correctly**. The path: Mike performs the manual push per this flow's steps done by hand, then runs `tropo-publish-release.py --version X.Y.Z --verify-only` so the entry still gets its remote-confirmed stamp. The refusal is the covenant, not a bug.

## If GitHub is unreachable

Builds are never hostage to an outage: `--offline` at build records itself in provenance (`publish_state: UNKNOWN`) and proceeds. Fire, by contrast, has no offline mode — the public act requires the public network, and verify-live requires the truth.
