## Purpose

Studio-tier extension per [close-cycle](3e0bb81e.md)'s own anticipated-extension text: *"Other Studios... may amend their dev-pipeline locally to add an explicit step after close-cycle — that's a Studio-tier extension, not OS-tier substrate."* This is that pattern, applied to housekeeping rather than git-commit.

Mike-directed 2026-07-14: Tropo Work should show a small amount of active/waiting work, most finished work archived, and evergreen projects easy to filter separately. Concrete evidence this was missing: a one-time catch-up sweep on 2026-07-13 (vela-v66) found 55 tasks/projects that were `status: closed/done` but never archived — 23 of the 30 stale projects were exactly this pipeline's own Activation Root scaffolding, accumulating at roughly one per run with nothing ever sweeping it. Filed as [5220fb25](5220fb25.md), corrected once it became clear this needed a declared pipeline step, not an engine code change.

## Cold-Boot Walk-Through

The cycle is closed (step 7). Before the pipeline-run itself terminates, the executor sweeps up everything that fed into this cycle's work:

1. **Find the loose ends.** Every task, note, and design-brief that fed into this cycle's work — linked via `member_of:`/`refs:` to this activation's work-items, or referenced from the dev-spec/release entry this cycle produced.
2. **Close what is genuinely done.** For each loose end: if the underlying work is actually complete, close it out per its own capsule's terminal transition (task → `status: closed, resolution: done` with a verifier; note → `status: closed`; design-brief → its own closed equivalent). **Do not force-close anything still legitimately open, blocking someone else's work, or ambiguous — leave it open and note it in the closing summary (step 5) rather than guess.**
3. **Archive what is closed.** Every task/note/design-brief closed in step 2 (or already closed but still `state: active`) gets archived via `python3 vault/tools/tropo-archive.py <uid> --reason "cycle <this-activation-uid> closed, swept at close-loose-ends"`.
4. **Archive the Activation Root project.** This pipeline-run's own scaffolding project (minted at step 0/1) gets archived the same way — `--reason "pipeline-run <activation-uid> completed"`.
5. **Record the sweep.** A brief summary of what got closed/archived (and what was deliberately left open, per step 2's caveat) goes into this pipeline-run's own closing substrate, so the sweep is auditable — not a silent bulk edit.

**This is not a re-litigation of step 7's ship decision.** Step 7 already closed the cycle; this step only cleans up bookkeeping that's already true in substance (work that finished but was never formally closed/archived).

## Known Enforcement Gaps

The declared exit criterion covers action 4 only — that the Activation Root project reached `state: archived`. Actions 1, 2, 3 and 5 (find the loose ends, close what is genuinely done, archive it, record the sweep) are executor judgment with no machine check, so a run can verify green having archived the root and swept nothing.

Reaching this step at all was honor-system at authoring: [1d689277](1d689277.md) measured on 2026-07-22 that nothing forced a run here, and that cycles shipping through `tropo-build-release.py` plus manual field-flips never triggered it. The durable-closure weld authored under dev-spec [c392d833](c392d833.md) makes root-closure a side-effect of the ship gesture; this declared step remains the pipeline's terminal record of that invariant plus the sweep.
