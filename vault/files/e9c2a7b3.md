# Attendant Mode — Onboarding Gate

*v1.79 S7 walk decision (Mike Q1, 2026-07-03): Attendant Mode is opt-in, offered ONCE at onboarding, honest about token cost, never the default.*

## What Is Attendant Mode

Attendant Mode is a standing Po session with a self-wake heartbeat loop. The owner gets an always-on studio: Po monitors maintenance loops, surfaces findings proactively, and wakes herself when something needs attention — without the owner having to ask.

**Proven mechanism:** the wake-loop pattern (established in the studio). **Honest about cost:** a Po session costs tokens; the onboarding offer states roughly what "always-on" costs in practice.

## The One-Time Offer

Po delivers the Attendant Mode offer ONCE, during the onboarding consent conversation. The exact wording is in the Po voice-template (`vault/files/8b1d4f9a.md` §Attendant Mode Line).

**After the offer:**
- Owner accepts → Attendant Mode is activated; Po writes a flag to `.tropo/flags/attendant-mode-enabled.flag`
- Owner declines → the flag is NOT written; Attendant Mode is never offered again this studio

**Gate file:** `.tropo/flags/attendant-mode-offered.flag` — written after the offer regardless of outcome, so the offer is not repeated. Zero bytes is fine.

## What "Never the Default" Means

- A fresh studio runs ZERO standing Po sessions before onboarding
- No maintenance fires before the consent conversation (consent_mode:ask on all loops)
- Attendant Mode is not activated by any executive, only by the owner's explicit choice in a Po session
- An executive (including Talos) MAY NOT activate Attendant Mode — only Po (with owner explicit consent) can

## Checking the Gate (for executives)

Before offering or describing Attendant Mode, check:
1. Does `.tropo/flags/attendant-mode-offered.flag` exist? → If YES: the offer was made; do NOT repeat it. If NO: the owner has not been through onboarding yet; direct them to Po.
2. Does `.tropo/flags/attendant-mode-enabled.flag` exist? → If YES: Attendant Mode is active; note it in the startup signal as "Attendant Mode active."

## Relationship to Maintenance Loops

Attendant Mode enables richer maintenance: Po can dispatch and narrate any loop (not just boot-time dispatch), can escalate findings into owner conversations, and can self-wake on a heartbeat. Standard maintenance (boot-fast-path 5.1.7) runs without Attendant Mode — it just dispatches and relays ONE line.

Attendant Mode is the escalation path, not the routine.
