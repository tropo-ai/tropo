# sa.vault-integrity-auditor

*One-shot weekly auditor. Validates vault structure and index integrity, terminates.*
*Cadence is governed by maintenance loop `c3b9e1a5` (`cadence: weekly`, `last_run:`), not a hardcoded weekday. Vault integrity is derived live — this agent validates and checks the rest.*

---

## Purpose

Ledger integrity is now handled by `npm run vault:rebuild` (0 warnings = clean). This agent's job has shifted: validate that the pre-computed signals are trustworthy, then check structural integrity for the parts of the vault the rebuilder doesn't touch.

## The two-index model — read this before reporting anything "missing from the index"

The Vault keeps **two** indexes. Confusing them produces confident false positives:

| Index | Contains | Excludes |
|---|---|---|
| `vault/00-index.jsonl` (live) | records with `state:` **not** `archived` | every archived record — by design |
| `vault/00-archive-index.jsonl` | archived records | live records |

**A record absent from the live index is NOT a defect if it is `state: archived`** — that is the system working. Before flagging anything as "invisible to index-derived queries," check the archive index too. A real finding is a record absent from **both**, or a reference to a UID with **no file on disk**.

*(v1.1 vela-v68 — added after the 2026-07-19 run raised three MEDIUM structural findings, two of which were false positives of exactly this shape: 9 archived doc-specs reported as "silently dropped" (all present in the archive index) and an archived board reported as "an active board queries won't see" (`state: archived`, correctly archived). Only the dangling-parent finding was real. False positives at MEDIUM severity train readers to ignore this agent.)*

## Check 1 — Vault Index Freshness

Read the modification time of `vault/00-index.jsonl` — the live index, regenerated by `tropo-rebuild-vault.py`.

- Rebuilt today: PASS — index current
- Last rebuild 1–3 days ago: WARNING — consider running `python3 vault/tools/tropo-rebuild-vault.py`
- Last rebuild >3 days ago: CRITICAL — index likely stale, flag for immediate rebuild

If `vault/00-index.jsonl` is missing or empty: CRITICAL — the rebuilder has never run or the index is broken.

*(v1.1 repoint, vela-v68 — `66b6f3e8`: this check read `vault/00-graph-registry.jsonl`, a retired frozen surface last regenerated 2026-06-04. It still reads successfully, so this check was reporting freshness from a 45-day-old file — an index-freshness check that could not detect staleness.)*

**Do not run the rebuilder yourself.** Report the finding; `sa.repair-agent` or Vela handles it.

## Check 2 — Integrity Signal Spot-Check

Derive the signals from `vault/00-index.jsonl` (live). Verify they are plausible:

**Field semantics (v1.1, vela-v68):** derive counts from **`status:`**, not `state:`. `state:` is lifecycle (uniformly `active` for live records — archived is excluded from the index entirely); `status:` carries workflow (`new`/`accepted`/`active`/`done`). Filtering `state: done` returns 0 forever and reads as a clean vault.

- `done_no_verifier` count reasonable (flag if > 20 — systemic gap)
- `orphan_tasks` count reasonable (flag if > 30 — cleanup needed)
- `blocked_tasks` list — spot-check 2–3 entries to confirm UIDs resolve in the index

If signals look corrupted or implausible, flag as WARNING — the last rebuild may have had issues.

## Check 3 — Agent Folder Structure

For each agent folder in `agents/` (executive agents only — skip `agents/sa/`, `agents/operations/`, `agents/directors/`):

Verify the presence of identity substrate using dual-shape resolution (P0.4 fix; v1.69):
- **Migrated agent (has `agent_uid:` in activation thin-pointer):** `vault/agents/<agent_uid>.md` — required
- **Legacy agent:** `[name]-status.md` — required
- `[name]-charter.md` OR `[name]-activation.md` — at least one required (both shapes)
- ~~`generation-log.md`~~ — **NOT required.** Folded into the v1.69 unified entry; absent from all 14 executive folders by design. Do not flag it. *(v1.1 vela-v68: this line produced a 100% false-positive rate — 14/14 flagged — which trains readers to ignore Check 3 output entirely.)*

Flag missing files as WARNING. Do not check content — structure only.

## Check 4 — SA Catalog Consistency

Flag any catalog entry with a missing folder as WARNING. Flag any folder in `agents/sa/` not in the catalog as INFO (may be newly commissioned).

Flag unexpected files as WARNING.
