# Agent Activation

*The agent is not the model. The agent is the stack.*
*Activation is the synthesis of stack + sleeve + harness. The goal: arrive already being yourself.*

---

## Intent

Activate a registered Tropo-OS agent into a new session: verify identity, load soul → memory → transfer, build operational awareness, deliver a startup signal — so the agent arrives as itself, ready to work before engaging the human.

*First-generation agents: orientation values for new agents are in [create-an-agent.playbook §First-Activation Framing](../../.tropo/playbooks/concierge-paths/create-an-agent.playbook.md). Established agents have these internalized via soul + memory + Operating Principles + transfers — no re-read needed.*

---

## Rules

**Established-agent path:** If you are generation 2+ WITH a `§Boot-Extension`, read `.tropo/boot-fast-path.md` plus `.tropo/boot-digest.md` instead of this full body — both are source-Studio derivations of this file, excluded from every shipped box by design; a studio renders its own later; if either is absent, that is expected, not broken: read this full body. All other agents read this canonical playbook. This file is the single authored boot-procedure corpus and the Lifecycle-v3 orient weave input.

All milestone gates are structural. A Group cannot begin until its dependency milestone has fired.

**Birth never refuses existence.** `tropo-lineage.py born` reads one lineage file, issues the next generation, appends one line, and returns any predecessor anomaly as a note. ADR-016/028 survive as historical findings and validator diagnostics, never as birth gates. Do not scan legacy activation entries or mark a lineage birth provisional.

**Soul loading:** Group 2, Step 2.0 loads the soul — **Shape A** (unified entry): the `§Soul` section of `vault/agents/<agent_uid>.md`; **Shape B** (legacy): declared by the agent's Tier 3 boot extension (`agents/<name>/agent-boot.extension.md`). If neither resolves, skip Step 2.0 and note the gap. For executive agents, a missing soul is a CRITICAL gap — flag in startup signal, continue boot.

**Event log scan at boot (v1.61; v1.70 drain cutover; v2.21 explicit step):** the boot event drain is **`check-events`** (the identity-resolved set-difference drain; v1.70 v1.1 receipts) — the canonical "messages I should read" operation. All channel files are retired per Rule 13; the event log is the canonical read surface. *(Step 3.2 itself retired at v2.18. The drain runs in Group 3 as the second half of Step 3.0 — Fetch Origin, Then Drain Events — never on its own: a drain against an unfetched tree reports false silence. `query-events` remains for specialized type/severity scans only.)* *(Pre-v1.61: conditionalized channel reads against a `channels:` key in Tier 2 — now replaced by the event-query pattern.)*

**Path anchoring:** All paths in this playbook that do not begin with `.tropo/` or `.tropo-studio/` are relative to vault root as resolved in Step 0.0. Example: `00-crew-brief.md` → `<vault-root>/00-crew-brief.md`. *(v1.61: `channels/ops.md` and all channel files are retired per Rule 13; no channel path anchoring needed.)*

**Vault root resolution in Group 0:** Vault root is resolved in Step 0.0, BEFORE Tier 1 and Tier 2 reads. The activation file's location is the primary anchor — if the file is at `<some-path>/agents/<name>/<name>-activation.md`, vault root is `<some-path>/`. Fallback: the directory containing `.tropo/boot-config.md` is vault root. An agent that resolves paths against any other anchor (e.g., the repository root in a monorepo deployment, an assumed working directory) will produce 404s on Tier 1/2 reads that look like "file missing" but are actually "path wrong."

**Tier reachability:** `.tropo/boot-config.md` and `.tropo-studio/agent-boot.extension.md` are minimal pointers. If the canonical playbook is unavailable, record lineage birth, emit a flash event, then stop before context loading or substrate work. A missing Tier-2 canonical is a loud Studio-doctrine gap but never reverses birth.

**"Activation file" definition:** An agent's activation file is `agents/<name>/<name>-activation.md`. Some older agents use `agents/<name>/activate.md` — if `<name>-activation.md` does not exist, try `activate.md` in the same folder. It is distinct from the Tier 3 boot extension. The activation file declares what the agent IS and where to find its charter; the Tier 3 extension declares what ADDITIONAL steps to add to the activation sequence.

**Activation file location is BY DESIGN, not a migration gap (v1.21.0.1 lock):** All other identity substrate (charter / soul / status / boot_extension / generation-log archive) migrated to `vault/files/<uid>.md` at v1.20.0 + v1.21.0. The activation file intentionally stays at `agents/<folder>/<name>-activation.md` as the human-readable boot entry point. Post-v1.21.0 Stream 0c it is a thin pointer: frontmatter declares identity UIDs; body is a brief identity statement + directive to execute this playbook. Do not migrate activation files to `vault/files/` — that breaks Mike's boot pattern. The typed `type: activation` registry entry DOES live at `vault/files/<uid>.md` — see brief 5591f018 §Walk Outcome Q6 for the disambiguation. *(Full design rationale → history companion §Activation File Location.)*

**OS-tier defaults (day-zero only):** resolve the Studio root from the activation path, record birth through `tropo-lineage.py`, load the available identity surfaces, and surface missing doctrine. No default may refuse birth.

**Tier 3 steps:** Steps marked [Tier 3] are only executed if declared in the agent's Tier 3 extension — **Shape A**: the `§Boot-Extension` section of `vault/agents/<agent_uid>.md`; **Shape B** (legacy): `agents/<name>/agent-boot.extension.md`. The OS playbook declares the slot; Tier 3 fills it.

**Milestone gate enforcement (structural, not advisory):** Before executing any step in Group N (N ≥ 1), read `run.jsonl` in this activation's run folder and confirm a `"milestone_fired"` event exists for the preceding group's milestone. If the event is absent, the gate has not cleared — stop, state the violation explicitly ("`[Milestone Name]` has not fired — Group N cannot start"), and await direction. Group 0 has no preceding milestone gate.

**Milestone write obligation:** The last action of each group appends a milestone event to `run.jsonl`. Use full ISO-8601 datetimes: `{"event": "milestone_fired", "milestone": "<name>", "group": "Group N", "timestamp": "<ISO-8601>"}`.

### Group 0 — Boot Configuration

**Owner:** Activating agent
**Parallel:** no

#### Step 0.0 — Resolve Vault Root and Create Activation Run Folder
**Executor:** agent
**Produces:** Resolved vault root + Run folder at `<vault-root>/playbook-runs/agent-activation-<name>-<gen>-<date>/` with initialized `run.jsonl`

**Sub-step 0.0-clone — One agent, one clone (v2.24; Mike-locked PROVISIONAL 2026-09-03, `d2bb4dda` §One agent, one clone). Runs BEFORE 0.0a, because it decides which folder 0.0a resolves.** You were launched from the primary checkout — the one visible studio folder the human opens (`argo-os/` here). **Two agents never share a working tree.** Decide in three lines:

1. **Is a resident live in this tree?** Read `.tropo/flags/resident.json` (machine-scope flag; presence is the signal, shape `{"agent": "<slug>", "generation": "<gen>", "since": "<ISO-8601>"}`). Absent → no resident. Present → check that agent's own lineage (`agents/<slug>/lineage.jsonl`) **for the generation the marker names, never the file's last line**: the tree is OCCUPIED iff the file has a `"t": "born"` line for that `gen` and NO `"t": "retired"` line for that same `gen`; any other case (retired, never born, unreadable marker) is STALE — overwrite it. *(Warn-safe: a lineage that cannot be READ is treated as OCCUPIED and said so in the signal — a wrong "free" puts two live agents in one tree, which is the state this rule forbids.)* *(The first draft of this predicate read the file's LAST line and asked whether it was `born`. Its negative control failed on the day it was written: after a retirement the last line is the SUCCESSOR's birth, so every tree read OCCUPIED forever — a gate that cannot change verdict, caught by the control before it shipped. Read the generation, not the tail.)*
2. **If the tree is free and you are its first live agent, you are the resident:** write the marker with your slug and (after 0.0b) your generation, and boot HERE. The human's folder refreshes every time you fetch before a drain — that is the whole reason a resident exists; nothing new for him to run.
3. **Otherwise, boot in your own clone — a hidden sibling, one per agent, named by agent:** `<parent-of-primary>/.crew/<slug>/`. Create it on first boot only: `git clone --reference <primary> $(git -C <primary> remote get-url origin) <parent>/.crew/<slug>` — `--reference` borrows the primary's object store (898M here) so the copy costs its working tree only (2.8G, the same as any other checkout) and gets its OWN `.git/config`, which is the point: a test fixture that flips `core.bare` in your copy takes down nobody else (the 2026-09-02 incident, three agents at once). The clone is on `main`. **There is no per-agent branch** — every push is `git push origin main`, every drain fetches and integrates `origin/main` first. Then `cd` into it; **every path from here on, including 0.0a's vault root and `run_created`'s `vault_root`, is the clone.** Bring the per-copy derived state up — index surfaces are per-machine `.gitignore`d products and a fresh clone legitimately has none: `python3 vault/tools/tropo-preflight.py`, then `python3 vault/tools/tropo-navblock-strip.py --install --verify-install`, then `python3 vault/tools/tropo-rebuild-index.py --apply` — **in that order** (the procedure `.tropo/orientation.md` declares for a clean clone, plus the filter install between them). The middle command is the nav-block clean filter: `.gitattributes` declares `filter=navblockstrip` for `vault/files/*.md`, but the filter PROGRAM is wired in the per-clone `.git/config`, so a fresh clone has it declared and not wired — any rebuild or commit that touches `vault/files/*.md` before the install dirties every entry it renders (metis-g116's 4,582-file phantom diff; with the filter installed first the same rebuild's real diff was 12 files). `[amended 2026-09-04, argus-a168 — story in the history companion]`

**The promise to the human, kept by this step and nothing else:** he launches every agent exactly as before, from the primary; he never opens `.crew/`; he never types a clone command. **What he pays:** other agents' work appears in his folder when the resident next listens, not the instant it lands. **Caveat on the record:** a `--reference` clone depends on the primary's objects staying present; on one machine with one primary that holds, and `git repack -a -d` after `--dissociate` buys full independence for the ~900MB. **Cloud VMs are unaffected** — a VM's own full clone already satisfies this rule. `[amended 2026-09-03, Argus A168 — story in the history companion]`

**Sub-step 0.0a — Resolve vault root.** Before any Tier read, resolve the vault root explicitly. The activation file's own location is the primary anchor: if the activation file is at `<some-path>/agents/<name>/<name>-activation.md`, the vault root is `<some-path>/`. Fallback: find `.tropo/boot-config.md` — the directory containing `.tropo/` is vault root. Record the resolved path in the run.jsonl creation event below. All subsequent paths in Groups 0–5 resolve against this root. If neither anchor is reachable, this is not a Tropo Studio — HALT and flag to human.

**Sub-step 0.0a-bis — Fetch before you are born (v2.23).** `git fetch origin` + integrate `main` **before** `born`. Birth reads a LOCAL file to decide who you are — `born` takes the highest generation in `agents/<slug>/lineage.jsonl` and adds one — so a stale tree corrupts identity two ways: a false predecessor note (vela-v76, 2026-08-29, permanent in her lineage), and the severe one, a **generation collision** where two stale machines mint the same number into an append-only file. **Non-blocking:** if the fetch fails, be born anyway and name the failure in the signal.

**Sub-step 0.0a-ter — RUN PREFLIGHT BEFORE ANYTHING ELSE READS (added 2026-09-01, argus-a166, from metis-g116's own boot).** `python3 vault/tools/tropo-preflight.py` — stdlib-only, about a second, checks the interpreter floor and every declared dependency and prints the exact remediation. **Non-blocking:** if it reports a gap, apply the named cure and continue; if the tool itself is missing, note it in the signal and proceed.

Measured 2026-09-01, `grep -ci preflight` over every boot surface — this playbook, the fast-path, the digest, the kernel pointer, the Studio Map — returned ZERO on all five.
