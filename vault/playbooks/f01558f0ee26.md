# Create and Mount a Team Vault — Ceremony 2

*You are an engineer. You will create a new governed vault — its own
identity, its own manifest — and mount it into your studio so the crew can
work in it. Every step is a command. If a step needs interpretation, record
it in your walk notes; that is a defect in this document.*

## Step 1 — Create the vault root

```
mkdir <team-vault-root> && cd <team-vault-root>
git init && git commit --allow-empty -m "team vault root"
```

The mount gate requires a git repo (it pins the mount to a resolved commit).

## Step 2 — Mint the vault's own identity

The team vault is its own studio-shaped identity space. From ANY directory:

```
TROPO_MINT_STUDIO_ROOT=<absolute path to your team-vault-root> \
  python3 <studio>/vault/tools/tropo-mint-id.py --kind studio --minted-by <you>
```

This writes `.tropo/studio-identity.md` INSIDE the team vault root — its own
4-hex prefix and composite studio_id, minted once, never regenerated. Every
uid that vault ever mints carries that prefix; two laptops minting offline
cannot collide. If your own studio's tooling refuses for a missing manifest,
you targeted the wrong root — check the env var.

## Step 3 — Render the vault manifest

**Precondition for `AUDIENCE` (added 2026-09-04 by argus-a168, finding `f015bac58b28`):** the audience must be
an **active, resolver-visible** group — one that appears in `vault/00-group-registry.jsonl` with `status: active`.
A group the join ceremony (`join-a-teammate`) just landed is a **draft** at `groups/<group uid>.json` under the
studio root until its owner completes that ceremony's Step 5 (seal the draft → build, verify and install the
successor authority generation → rebuild the registry); a draft refuses at Step 4 below with
`[REFUSED] audience refused (B4a strict): GROUP_NOT_FOUND`. Rehearsed and refused exactly so on 2026-09-04, and
rehearsed to LAND the same day once Step 5 had run (argus-a169); do not mount before Step 5 of the join has run.

Still inside the team vault root, set these values and run the block. The
`uid` mint is the manifest FILE's governed identity: the current mint seam
reads this team root's studio identity and returns the WHOLE composite
12-hex value (`<4-hex mint_prefix><8-hex local>`) — never truncate it. The
separate `vault_uid` mint is the vault's ADR-050 short registered code.

```
STUDIO_ROOT="<absolute path to the Studio that supplies vault/tools>"
TEAM_VAULT_NAME="<team vault name>"
OWNER="<owner UID or label>"
AUDIENCE="<active group UID>"
REMOTE="<git remote URL>"
CURATOR="<curator UID or label>"
REGISTERED_TYPES="task,project,note"
CAPABILITIES=""  # comma-separated local names, or empty

TEAM_VAULT_ROOT="$(pwd -P)"
MANIFEST_UID="$(
  TROPO_MINT_STUDIO_ROOT="$TEAM_VAULT_ROOT" \
    python3 "$STUDIO_ROOT/vault/tools/tropo-mint-id.py" --kind file
)"
VAULT_UID="$(
  TROPO_MINT_STUDIO_ROOT="$TEAM_VAULT_ROOT" \
    python3 "$STUDIO_ROOT/vault/tools/tropo-mint-id.py" --kind vault
)"
export TEAM_VAULT_NAME OWNER AUDIENCE REMOTE CURATOR REGISTERED_TYPES
export CAPABILITIES MANIFEST_UID VAULT_UID

python3 - <<'PY'
import os
from pathlib import Path

import yaml

vault_uid = os.environ["VAULT_UID"]
registered_types = [
    value.strip()
    for value in os.environ["REGISTERED_TYPES"].split(",")
    if value.strip()
]
capabilities = [
    f"{vault_uid}:{value.strip()}"
    for value in os.environ["CAPABILITIES"].split(",")
    if value.strip()
]
manifest = {
    "uid": os.environ["MANIFEST_UID"],
    "vault_uid": vault_uid,
    "type": "vault",
    "name": os.environ["TEAM_VAULT_NAME"],
    "kind": "team",
    "owner": os.environ["OWNER"],
    "audience": os.environ["AUDIENCE"],
    "remote": os.environ["REMOTE"],
    "prefix_policy": {"references": "32067bea"},
    "publish_policy": {"who": "owner"},
    "curation_policy": {"mode": "gardener"},
    "curator": os.environ["CURATOR"],
    "version": "1.0.0",
    "status": "active",
    "contract": {
        "registered_types": registered_types,
        "capsule_versions": {},
        "capabilities": capabilities,
    },
    "regulated_acceptance": {"accepted": False},
}
frontmatter = yaml.safe_dump(manifest, sort_keys=False)
Path(".tropo/vault-manifest.md").write_text(
    f"---\n{frontmatter}---\n\n# {manifest['name']}\n",
    encoding="utf-8",
)
PY

git add .tropo/studio-identity.md .tropo/vault-manifest.md
git commit -m "Create team vault manifest"
```

Read the rendered manifest before mounting it. If `CAPABILITIES` is non-empty,
the renderer qualifies each local name as `<vault_uid>:<name>`; qualification
and the `.tropo-studio/compose.lock` key both use `vault_uid`. The manifest's
governed record identity remains `uid`. They are distinct fields from distinct
mint domains, and neither may substitute for the other. The mount gate validates
this file before anything else — a vault with no valid manifest is not
mountable, by design.

## Step 4 — Mount it into your studio

From the studio root:

```
python3 vault/tools/tropo-mount.py \
  --mount-path <absolute path to your team-vault-root> \
  --consent --mounted-by <you>
```

`--consent` is a governed write, not a prompt click-through: you are
recording executable consent for the capabilities the manifest declares.
Success lands a record in `.tropo-studio/compose.lock` pinned to the vault's
resolved commit hash. Refusals leave the lockfile untouched — the gate's own
rule. Common ones:

- *manifest missing or invalid* — step 3 was skipped or malformed.
- *not a git repo* — step 1 was skipped; the gate cannot pin a commit.
- *one-clone-per-vault-UID* — this `vault_uid` is already mounted; re-mounting
  or updating requires `--force-remount`, deliberately.

## Step 5 — Confirm

```
python3 -c "import json; print(json.dumps(json.load(open('.tropo-studio/compose.lock')), indent=1))"
```

Your vault's record is pinned. Skills it ships are name-qualified
(`<vault>:skill`) — never ambiguous with studio-local ones. Teammates joined
through Ceremony 1 author into the mounted tree, and their work derives the
team-shareable class at the publish boundary.

## What you do NOT do

- No hand-editing of compose.lock — the gate is the only writer.
- No mounting of a vault whose manifest you have not read. Consent you have
  not read is not consent.
- No second identity mint for the same root. Genesis is once, forever.
