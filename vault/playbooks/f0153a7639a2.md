# Join a Teammate — Ceremony 1

*You are Po, the concierge. A colleague is joining the team vault. You drive
every step; the org owner contributes exactly ONE gesture. You never touch a
signing key — that is the design, not a limitation (ADR-066: keys are external
and never minted by the agent lifecycle).*

*Every step below is a command or a handoff. If a step needs interpretation,
that is a defect in this document — record it in your walk notes.*

## What this ceremony does

Three things land together or not at all:

1. The colleague's **principal record** — uid minted composite (12-hex) through
   the same identity seam every file uses.
2. A **successor group generation** — a NEW immutable generation including the
   new member. Nothing is amended (B4a has no mutate; a join adds a generation).
3. The **residency field** on the principal — the one fact the publish boundary
   reads to let their work cross. Written only by this ceremony, read only by
   the scope derivation.

## Step 1 — Prepare the bundle

```
python3 vault/tools/tropo-join-teammate.py prepare \
  --colleague-name "<Full Name>" \
  --group-slug <the team group's slug>
```

You get two lines: `BUNDLE <path>` and `DIGEST <64 hex>`. The bundle writes
nothing governed — it is a proposal. If you see a refusal about a missing
studio-identity manifest, the studio has not run its genesis; that is a
stop-and-surface, not something to work around.

## Step 2 — Hand over ONE digest

Give the org owner the bundle path and the digest, by your normal channel.
The owner signs the digest with their Ed25519 key and returns the signature
(64 bytes, hex). One gesture. If they ask you to sign it, or to hold their
key, refuse — the signature IS the authorization, and an agent custody of it
would make the whole ceremony theater.

## Step 3 — Apply with the owner's gesture

```
python3 vault/tools/tropo-join-teammate.py apply \
  --bundle <path from step 1> \
  --signature <hex from step 2>
```

Success prints `JOINED principal=<uid> group=<slug> by=<owner uid>` — UIDs,
never names. All three legs landed. Refusals you may hit, each leaving
everything untouched:

- *signature does not verify* — the bundle changed after prepare, or the
  signer's key is not the accepted owner key. Nothing lands. Re-prepare.
- *principal already exists* — this colleague already joined. A re-join is a
  new bundle for a new person, never a re-apply.
- *trust file absent* — no owner key is accepted on this machine. Keys are
  accepted out of band, by fingerprint comparison, before any ceremony.

## Step 4 — Confirm

```
python3 -c "import json; rows=json.load(open('.tropo-studio/group-authority/principals.jsonl')); print([r for r in rows if r['principal_uid'].startswith('<principal uid prefix>')])"
```

The record shows `residency: team-resident`. From this moment, any governed
record that colleague authors with no explicit scope derives the
team-shareable class and can cross the publish boundary — because of who they
are, not where the file sits.

## Step 5 — Make the group resolver-visible (the OWNER's follow-through; the ceremony is not over at Step 4)

*Added 2026-09-04 by argus-a168 on finding `f015bac58b28`; rewritten the same day by argus-a169 to the sequence
that was REHEARSED to land (the first version's five commands all refused — Metis G118's rehearsal recipe R1–R10).
`apply` lands the group as a **draft** at `groups/<group uid>.json` under the studio root — the same `groups/`
the studio's shipped groups live in — and a draft is absent from every registry and resolver by the group
capsule's own Rule 5. Nothing downstream can see it (the mount gate in `create-and-mount-a-team-vault` refuses
`GROUP_NOT_FOUND`) until the owner seals it and installs a successor authority generation. Those are signed,
one-shot authority acts, which is why the join does not do them for you.*

Run everything below **from the studio root**. Every value is READ from the installed pin and the trust file,
never typed from memory. The owner's signing key is used in 5c only, by the owner: Po never holds it.

```
PIN=.tropo-studio/authorities/group-authority/installed.json
TRUST=.tropo-studio/trust/group-authorities.json
AUTH_UID=$(python3 -c "import json;print(json.load(open('$PIN'))['authority_uid'])")
PDR=$(python3 -c "import json;print(json.load(open('$PIN'))['principal_directory_revision'])")
GEN=$(python3 -c "import json;print(json.load(open('$PIN'))['generation_dir'])")
KEY_UID=$(python3 -c "import json;print(json.load(open('$PIN'))['signing_key_uid'])")
NEXT_GEN=$(python3 -c "import json;print(json.load(open('$PIN'))['authority_generation']+1)")
PRIVATE_GROUP_UID=$(python3 -c "import json;print(json.load(open('$GEN/audience-policy.json'))['legacy_aliases']['private'])")
FINGERPRINT=$(python3 -c "import json;print([k['sha256_fingerprint'] for k in json.load(open('$TRUST'))['accepted_keys'] if k['key_uid']=='$KEY_UID'][0])")
GROUP_UID=$(python3 -c "import json;rows=[json.loads(l) for l in open('.tropo-studio/join-bundles/journal.jsonl') if l.strip()];print([r for r in rows if r['event']=='join_committed'][-1]['journal']['group_draft_uid'])")
CORPUS="$(pwd -P)"

# 5a. the principal directory for the seal: the installed generation's claims PLUS the colleague the join just
#     minted, re-issued under this authority (the join records them as source_authority_uid "local-prepare",
#     which the authority build refuses). A uid -> claim MAP: the finalizer reads a map, not the pin's JSONL.
python3 - "$GEN" "$AUTH_UID" <<'PY'
import json, sys
gen, auth = sys.argv[1], sys.argv[2]
claims = {}
for line in open(f"{gen}/principals.jsonl"):
    if line.strip():
        c = json.loads(line)
        claims[c["principal_uid"]] = {k: c[k] for k in ("principal_uid", "principal_class", "status", "source_authority_uid", "source_revision")}
for r in json.load(open(".tropo-studio/group-authority/principals.jsonl")):
    claims.setdefault(r["principal_uid"], {"principal_uid": r["principal_uid"], "principal_class": r["principal_class"],
                                           "status": "active", "source_authority_uid": auth, "source_revision": "1"})
json.dump(claims, open(".tropo-studio/join-bundles/step5-principals.json", "w"), indent=1, sort_keys=True)
print("principals for the seal:", len(claims))
PY

# 5b. seal the draft into the corpus (one-shot; refuses if the draft is malformed or already sealed)
python3 vault/tools/tropo-finalize-group.py finalize --corpus-root "$CORPUS" --draft-uid "$GROUP_UID" \
  --authority-uid "$AUTH_UID" --principal-directory-revision "$PDR" \
  --principals-file .tropo-studio/join-bundles/step5-principals.json

# 5c. build, verify and install the SUCCESSOR authority generation, chained to the installed one — the OWNER's
#     gesture with the OWNER's key file (never Po's; ADR-066: keys are external)
python3 vault/tools/tropo-group-authority.py build --corpus-root "$CORPUS" --authority-uid "$AUTH_UID" \
  --signing-key-uid "$KEY_UID" --authority-generation "$NEXT_GEN" --previous-envelope-file "$GEN/signed-envelope.json" \
  --private-group-uid "$PRIVATE_GROUP_UID" --signing-key-file <the owner's key file> \
  --principals-file .tropo-studio/join-bundles/step5-principals.json
python3 vault/tools/tropo-group-authority.py verify  --corpus-root "$CORPUS" \
  --bundle-dir .tropo-studio/authorities/group-authority/build --expected-fingerprint "$FINGERPRINT"
python3 vault/tools/tropo-group-authority.py install --corpus-root "$CORPUS" \
  --bundle-dir .tropo-studio/authorities/group-authority/build --expected-fingerprint "$FINGERPRINT"

# 5d. re-project the registry deterministically and verify parity
python3 vault/tools/tropo-rebuild-group-registry.py rebuild --corpus-root "$CORPUS"
python3 vault/tools/tropo-rebuild-group-registry.py verify  --corpus-root "$CORPUS"
```

**Confirm:** the group uid appears in `vault/00-group-registry.jsonl` with `status: active` and
`source_path: groups/<group uid>.json`, and `install` printed a `registry_row_count` one higher than before.
Only now is it a legal `AUDIENCE` for a team-vault manifest. If a step above needed interpretation, record it — it
is a defect in this document.

## What you do NOT do

- No `--authorized-by` anything. There is no second authorization channel.
- No key generation, storage, or transport. Ever.
- No hand-editing of principals, groups, or residency. One writer: this tool.
