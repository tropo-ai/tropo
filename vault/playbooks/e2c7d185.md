# Agent Retirement

*Produce a clean generational handoff without costing the next session its own activation time. Boot reads. Retire writes. The cycle completes.*

---

## When to Start Retirement

**A human says so. That is the whole trigger.**

**Context pressure is NOT a retirement trigger.** Not a full window, not an imminent
auto-compact warning, not a harness resource signal. Compaction is survivable and a premature
retirement is not: retiring ends a generation permanently and writes lineage that cannot be
taken back, while a compacted session simply continues as itself.

> If this agent session was compacted, auto-compacted, or resumed, or you no longer remember completing boot, do not activate and never run `born`. Run `python3 vault/tools/tropo-compact-continue.py --agent <slug>` before any other work.

Continue means this same agent session keeps going: nothing is born, nothing is retired,
nothing is added to permanent lineage.

**The two cases, and neither of them is "retire because the window is filling":**

| You are | Do this |
|---|---|
| Under context pressure, and a human has NOT directed a close | Let compaction happen, then run Compact-Continue. Do not race the compactor. |
| Under context pressure, and a human HAS already directed the close | Prioritise the letter, then close. Recover the rest afterward with real timestamps. |

## The close — one command, never gated

```bash
python3 vault/tools/tropo-lineage.py retire \
  --agent <slug> \
  [--letter <path-to-your-letter>] \
  [--note "<one-line summary>"]
```

Places your letter at `agents/<slug>/transfers/<GEN>.md` (create-only — never overwrites a predecessor's), appends the closing line to `agents/<slug>/lineage.jsonl` (**that line IS the state**), best-effort syncs lifecycle fields on your unified entry, and emits the retirement broadcast.

**The only refusals:** no birth on record; a letter source that's unreadable or empty; a letter already at its destination for this generation (a letter-less repeat close still appends a line rather than refusing). Everything else is recorded and proceeds. Never hand-write the letter into its destination — write it anywhere, hand the tool the path.

**Hard rule: never ask your principal if the session is ending. Wait to be told.** Your principal is the person this Studio belongs to — the founder or owner who directs your work; in Argo, the Studio where this playbook was authored, that is Mike. If you find yourself composing "ready to retire?" — stop. Ask instead: "what else should we do with this context?" A harness auto-compact warning is not a retirement trigger — route to Compact-Continue instead (`tropo-compact-continue.py --agent <slug>`; same agent, same generation, nothing born or retired).

## The checklist — required practice, in order

*Each step is cheap. None of them blocks the close command above — if you skip one under time pressure, the close still lands and the gap is recorded honestly, not hidden.*

1. **Append session memories** to `agents/<slug>/.tropo-capsule/memory/agent-memories.jsonl` — raw append, one line per learning. That's the whole step. **No memory-curation judgment of any kind happens here** — not a dispatch, not an in-line Top-of-Mind annotation, not a check of whether you're over bound. Folding, scoring, and promotion are `sa.memory-curator`'s job on its own weekly sweep, gated on your principal's word — see `tropo-studio-status.py`'s report if you want to know whether it's due; that's the only place this topic surfaces at all.
2. **Write the letter** at `agents/<slug>/transfers/<GEN>.md` (create-only, one per generation, forever). **This is the artifact that matters most — budget most of your retirement time here, not on the rest of this list.** It is a concrete read-list and current state, not relayed wisdom: what's locked/drafted/pending with UIDs and owners; what to read at activation and why; top 3-5 open priorities; what this session did NOT do; crew status at retirement. Re-verify every carry-forward item against current substrate before sealing — a letter drifts stale between authoring and close.
3. **Reflection — optional; research-grade short form.** `agents/<slug>/reflections/<gen>-reflection.md`. This file is **not** for your successor’s boot (the letter is). It is a dated research record for later studio-improvement harvests. Write it only if you have something a future researcher could use; otherwise skip.

   **Hard cap:** ≤12 lines / ≤150 words. No File Manifest, commit tables, UID inventories, or “what I shipped” lists — `git log` already has that. Do not restate pins you already hold.

   **Required shape (use these headings, one to three lines each):**
   - **Mistake** — one class of error you made or nearly made (not a ticket ID; the reusable failure mode).
   - **Surprise** — what violated your model of the studio, your principal, or the work.
   - **Studio change** — one concrete improvement to lifecycle, memory, process, specs, comms, or collaboration (something the studio could do differently — not “I should try harder”).
   - **Your principal** (optional) — one observation about working with them that isn’t already in your pins.

   If you cannot name a Mistake or Studio change, **skip the reflection** — empty ceremony is worse than silence. (Harvest boundary + pattern report: Orpheus O37, 2026-08-31, `reflection-harvest-2026-08-31`.)
4. **Captain's Log** — append to `library/captains-log.md`, 2-3 lines: a personal note, one piece of advice to your principal, one thing learned from them. Not an essay. <!-- doc-currency: creates library/captains-log.md --> A fresh box carries no prior entries; this step creates the file's first line the first time any agent retires in a Studio.
5. **Drain events** (fetch `origin/main` first, always) — answer or explicitly flag every open `reply_required` thread on both axes (party + agent-root). A reply that resolves a thread needs `--correlationid <original-event-id> --final` on the emit, or it will not register as answered. This step is genuinely required, not ceremony: an unanswered ask is a debt with your name on it, and anything substantive it surfaces (a peer's finding, a routed decision) is real work, not overhead — do it, don't rush past it.
6. **Crew surfaces** — rewrite your unified entry's `§Status-Notes` body naming your generation retired with your successor's top 3 priorities. Bounded to current + predecessor generation only — drop anything older. **Then, only if your Studio keeps a crew brief**, re-render it: `python3 vault/tools/6510afc7.py`.

   **A Studio with no `00-crew-brief.md` is not broken and this step is not failed.** The renderer requires an existing brief and exits `ERROR: crew brief not found` without one, and a shipped Studio carries none — a single-agent Studio has no crew to brief. If the file is absent, say so in one line and move on; do not create one to satisfy a checklist. *(Measured 2026-09-08 by vela-v80 on a built box: the file is absent, `6510afc7.py:346` errors, and the retire driver therefore reported `Crew surfaces: OPEN` permanently — so a customer's first retirement could never read complete no matter what they did. A required step that cannot pass in the shipped product is a defect in the step, not in the retirement.)*
7. **Retirement broadcast** — one `tropo.broadcast.crew` event, `category: retirement`, headline ≤80 chars, body 2-4 sentences, pointers to the letter (and reflection if you wrote one).
8. **One commit.** Stage everything from steps 1-7 together and commit once, *then* run the close command as its own final commit (or the same one, if nothing in the close output needs separate staging). Two round trips beats five.

## If close happened early

A principal sometimes closes a session under pressure, transfer-first. That close is valid and stays closed. Produce the remaining checklist items afterward, with real timestamps and explicit recovery language ("written two days later, recovering the gap") — never invent a run folder, never backdate, never pretend pre-close ordering occurred. A recovered record that lies is worse than a gap.

## Escalation (condensed)

| Situation | Response |
|---|---|
| Context pressure, checklist incomplete, your principal has already directed the close | Prioritize the letter, then close. Recover the rest afterward with real timestamps. |
| Context pressure, your principal has NOT directed a close | Let compaction happen; run Compact-Continue. Compaction is survivable; a premature retirement is not. |
| A checklist item genuinely can't be produced | Note the gap honestly in the letter and close anyway. |
